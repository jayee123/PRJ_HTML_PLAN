一、現況總覽

16 張截圖都來自「羽升幸福養成學苑」——目前唯一一支課程 App 的老師端後台，加上前台的對話式介面（21 天練習 / 我卡住幫我拆）。這正是規格書第 0 節所說的「上一版：單一課程 App」，也是這次要拆出公版的原始素材。

模組目前歸屬公版化判斷
統計總覽 / 用戶管理單一老師視角要拆出 Super User 版本，屬公版
線上課程管理 / 實體課程管理該課程專屬內容編輯器本體屬私版，「上架殼」欄位屬公版
訂閱管理 / 付款記錄綁在單一課程方案上應改為帳號層級一套，屬公版核心
報名紀錄 / 通知管理單店鋪資料引擎共用、資料依老師分流，屬公版
AI 對話紀錄 / 記憶管理 / Token 統計 / 學習進度課程與用戶對話歷程內容屬私版，但需補上租戶關聯欄位

二、會員 / 帳號系統

公版規格第 2 章的第一優先項目，也是規格書建議「先做垂直切片」的入口。

帳號主鍵改為 Email

新增 高優先 · 7/25
現況（截圖依據） 用戶管理表把「手機」放在最醒目欄位，Email 只是姓名下方的次要文字；訂閱、報名、付款各表也都用手機當查詢鍵。
Udemy 對照 帳號 = Email／OAuth，一次登入即可看到所有已購課程與學習歷程，帳號與課程內容完全解耦。
工作項目
  • 用戶表新增「Email 已驗證」「驗證信發送時間」欄位，Email 提升為主要顯示鍵
  • 手機號欄位改為灰色選填，退到次要位置（規格 2.4）
  • 各查詢框（搜尋用戶／訂閱／報名）預設以 Email 搜尋，手機為輔助

註冊流程一步驟化 + 驗證信

新增 高優先 · 7/25
工作項目
  • 個人資料頁與建立資料頁合併成單頁表單（Email／暱稱／手機選填／生日選填）
  • 寄送驗證信 + active 連結，取代兩次輸入 Email 的舊做法
  • 邀請碼欄位保留但預設關閉，留給測試期使用

三、首頁 / 導覽頁（一票玩到底）

16 張截圖裡完全沒有「多 App 選單首頁」——目前登入後直接進單一 App。這塊要從零設計，也是使用者第一眼看到「這是書城而不是單一課程」的地方。

App／課程卡片首頁

新增 高優先 · 8/10
Udemy 對照 課程卡片標準欄位：縮圖、標題、講師、評分星數、學生數、價格；可篩選分類／評分／價格。但商業模式更接近 Netflix／迪士尼樂園年票——一次付費、卡片式列出「可玩設施」，而不是逐堂購買，這點規格書已經點名。
工作項目
  • 設計共用「App 卡片」元件：縮圖、名稱、一句話說明、所屬老師、狀態（可用／即將上線）
  • 即使初期只有 1 支 App，也照多 App 版型建置，避免未來每加一支 App 就要重做版面
  • 先不做 Udemy 式搜尋／評分系統（依會議「務實而非銀行級精準」原則），列表式卡片即可

首次導覽頁（90 秒預告）

新增 中優先 · 8/10
工作項目
  • 建立 user_app_seen 這類簡單狀態表，記錄「已看過導覽頁」，不需要複雜設計
  • 第二次以後進入右上角「✕」可直接關閉，對照 Udemy「課程介紹頁 + 免費試看片段」的概念

四、訂閱 / 付款 / Token（金流公版核心）

這是目前系統與規格書落差最大的一塊——現有訂閱資料是「以課程為單位」，跟「一票玩到底」的帳號層級訂閱互相矛盾，建議列為優先對齊項目。

訂閱脫鉤成帳號層級

架構落差 優化 高優先 · 8/31
現況（截圖依據） 訂閱管理表「服務」欄位固定顯示「MBTI 幸福關係」，方案名稱同時出現 Premium／基本方案／進階方案，金額分別是 NT$100／300／490／890，命名和金額都沒有統一邏輯。
工作項目
  • 方案統一命名為 Basic／Advance／Premium 三檔，移除中文混用的「基本方案」「進階方案」
  • 訂閱資料改為綁在帳號上，「服務」欄位轉為「最後使用的 App」顯示用途，不再是訂閱主體
  • 付款記錄的方案名稱同步統一，避免同一使用者的付款紀錄出現兩套命名

Token 額度上限 + 即時告警

新增 保留既有報表 高優先 · 8/31
現況 Token 使用統計頁只有「歷史用量報表」（按日期／用戶／服務三種檢視 + CSV 匯出），沒有「上限控管」或「即將用完告警」機制。
工作項目
  • 每人每期設 Token budget cap，搭配即時用量監控，到上限即提示升級（規格 11.4）
  • 7 天免費試玩到期／額度到達上限，觸發通知管理裡的新通知類型
  • 三種檢視維度＋CSV 匯出的資料結構保留，直接擴充到跨老師、跨 App 維度即可，不需重做

五、系統 / 店鋪三層架構

目前後台只存在「單一老師視角」，完全沒有 Super User（平台方看所有老師）畫面，也沒有 tenant_id 切換機制——這是公版規格第 4 章的核心，也是荃宇分工裡「參考小鵝通／丁丁架構」要交付的主體。

老師身分（tenant_id）貫穿所有表

新增 高優先 · 8/31
Udemy 對照 Udemy Instructor Dashboard（老師只看自己課程的營收與學生）對比 Udemy 平台方後台，是最直接的參照；小鵝通／丁丁的多店鋪後台也是同一邏輯。
工作項目
  • 用戶管理／課程管理／訂閱／付款每張表加上 tenant_id
  • Row-Level Security：老師登入只看自己教的課程與學員；Super User 可切換查看所有店鋪
  • Super User 總覽儀表板：跨老師的總營收／總用戶／總活躍度
可直接沿用 現有統計總覽頁的卡片式 KPI（總用戶數／本月營收／活躍用戶／本月報名 ＋ 趨勢圖 ＋ 近期活動）資訊架構清楚，Super User 版可複用同一套元件，只是資料範圍從單店鋪換成全平台。

六、課程上架共用殼（「上架一本書／一個課」）

章節／單元編輯器與實體課程看板本身做得堪用，屬於私版內容範圍；荃宇要定義的是外面那層「上架殼」——公版共用欄位。

上架殼欄位定義

新增 編輯器保留 中優先 · 9/15
Udemy 對照 建立課程精靈式流程（基本資料 → 大綱 → 定價 → 發布），課程卡片標準欄位（封面、標題、講師、評分、價格），是上架殼最小欄位集的參考基準。
工作項目
  • 定義上架殼共用欄位：封面圖、一句話簡介、分類標籤、老師名稱、對應定價方案
  • 依規格第 5 章原則：每談成一個新課程再增列私版欄位，不預先窮舉（例如奇門遁甲的盤面資料、幸福關係的 MBTI 狀態）
可直接沿用 章節／單元編輯器（拖拉排序、影片連結、PDF／PPTX 教材上傳）與實體課程看板（規劃中／報名中／進行中／已結束）都不需大改，直接當私版內容編輯核心。

七、保留清單彙總

避免重工——這些既有設計已經驗證堪用，公版化時直接抽成共用元件即可。

保留
側邊欄「總覽／課程／營運／AI」分組邏輯清楚，之後只要在最上方加一個「App／店鋪切換器」，不需重新設計導覽結構。
保留
各列表頁「搜尋列 ＋ 篩選下拉 ＋ 匯出 CSV」的一致模式，可直接抽成公版共用元件，往後每個新模組都能套用。
保留
Token 使用統計的三維度檢視（按日期／用戶／服務）資料結構良好，公版化時只需擴充維度，不必重新設計。
保留
AI 對話紀錄／記憶管理的分類標籤（目標／關係／個性）與時間戳機制已經可用，私版內容不動，只需補上租戶關聯欄位。
